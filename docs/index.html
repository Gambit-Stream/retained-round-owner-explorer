Which gate changes the next action?

The first failed gate sets the primary status. The complete gap list retains the remaining unresolved conditions. These are authored review rules; your provider contract determines the actual behavior.

Ordered review gates and their boundaries
GateConditionNext accountable action
1. AuthenticityCallback origin not establishedHold ownership selection. Verify the callback through the agreed mechanism.
2. MappingMissing, conflicting, wrong operator or expiredResolve exact identity scope and valid retained record. Do not substitute the new-round default.
3. Event intentRepeated event has changed payload referenceEscalate the mismatch before accepting duplicate semantics.
4. Handler accessOriginal handler is unavailableRestore evidence access or review a recovery path. Preserve the historical owner.
5. Original resultUnresolved or assumed recordedReconcile the original reference or review its recorded result against the response contract.
6. ReviewerNo exception reviewer assignedKeep the assignment gap visible. A named handler is not an accountable human reviewer.

"Gateway A owned this round" and "the wallet effect completed" are separate statements. A mapping can support the first while the second remains unresolved.

What belongs in the retained record?

Preserve identifiers under the scope agreed for your integration. This example uses operator, provider and round together. Some interfaces need additional dimensions, such as environment or product, to distinguish records.

Ownership reference
Original handler plus a versioned mapping and its validity interval. Keep the cutover decision separate from the current routing setting.
Event identity
The provider event identifier and original operation reference. Establish which repeats are semantically the same operation.
Result evidence
The original response or ledger lookup reference, its observation time and unresolved fields. A callback receipt alone is not a confirmed balance change.
Exception assignment
A reviewer, the next evidence request and a review checkpoint. Assigning a person does not settle the event.

The demo labels mapping-v7 and receipt-41 are invented references. They are not cryptographic hashes, real logs or proof of a completed lookup.

Reproduce the model and inspect its limits

  1. Load a preset and note its six assumptions.
  2. Change one input. Compare the primary action with the complete evidence-gap list.
  3. Download JSON or CSV. Compare the exported input values and rule version with the visible record.
  4. Use the public source and test suite to inspect the evaluation order. Run node --test test/explorer.test.mjs with Node.js 23 or later.

The executable suite enumerates all 160 input combinations and checks that none grants wallet authority. This checks the authored local model. It does not test a casino platform, provider callback, signature verifier or wallet.

No live records can be entered or uploaded here. The page makes no provider calls and stores no scenario in browser storage. GitHub serves the page and assets; downloaded files are created in your browser. The model does not establish retention periods, settlement finality or a production recovery procedure.

If the provider contract allows reassignment of open rounds, preserve the explicit migration evidence and adapt the model. Simply editing the current default is not that evidence.
