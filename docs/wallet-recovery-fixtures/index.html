iGaming Wallet Recovery Fixtures: Session, Route and Decision Contracts

Four original synthetic Python examples from published technical articles, packaged as separate cases. The observed corrected result is 46 passing test methods across four independent subprocesses.

The package contains runnable examples and retained execution evidence. It makes no production security, concurrency or performance claim.

Reproduce the retained result

From the extracted directory, using Python 3 with the standard-library SQLite module:

python3 run.py
python3 run.py --verbose

The retained execution used CPython 3.14.7. Other Python versions and operating systems have not been verified. No installation or credentials are needed.

The first command produces these stable result lines:

01-session: PASS (7 tests)
02-route: PASS (9 tests)
03-export: PASS (16 tests)
04-decision: PASS (14 tests)
TOTAL: PASS (46 tests)

The runner copies each case into a fresh temporary directory, launches its own Python subprocess and removes that copy afterward. It selects corrected Frame and Router explicitly and removes ambient negative-control selectors. Python environment overrides are ignored. Original sources and packaged cases remain unchanged. A nonzero subprocess exit or an unexpected test count makes the runner fail.

Case contracts and limits

Four isolated synthetic cases and their tested boundaries
DirectoryTested contractBoundary
01-sessionReconnect looks up the original immutable operation; retained rejection stays rejected after replenishment; unavailable history stays UNKNOWN. Seven methods.In-memory sequential model with integer USD minor units. Fake session registry; no browser, iframe SDK or durable journal. Default in the original test file is deliberately buggy; use the runner for the corrected variant.
02-routeLate positive-credit events use the retained round owner; duplicates and changed payloads remain distinct; an unavailable old route requires explicit held-event retry. Nine methods.In-memory sequential records. No money movement, signature validation or final-settlement semantics. Supported processing entry points are callback and retry_held; helper apply alone does not deduplicate.
03-exportReconstruct account histories with brand/player/currency ownership checks; expose malformed packages and unresolved exceptions. Sixteen methods.Four invented events across two accounts. File hashes do not authenticate the source. READABLE_WITH_UNRESOLVED authorizes no retry and establishes no complete player lifecycle.
04-decisionRecover the retained cashout decision after an offer changes or expires; replay accepted requests without a second effect; roll back the injected interruption. Fourteen methods.One local SQLite connection, simulated integer units and a supplied clock. A database reopen is tested; distributed durability and concurrent acceptance are untested.

These fixtures call no network, provider or real wallet. They are examples to inspect, not deployment or financial advice.

Integration scope

The Gambit Stream sportsbook iframe integration scope gives commercial context for the session-recovery example. The synthetic fixture does not establish how any provider behaves.

The archive includes provenance.json, which pins each original module, test and retained input by source snapshot and SHA-256. It distinguishes committed source matches from local retained snapshots; it does not claim a mutable article revision ID.

expected-results.json records commands, runtime and passing test names. The evidence directory contains actual test logs, two demo outputs and the export reader report. Test durations vary; compare status and method counts rather than log bytes.

The included modules were prepared for the four cited tutorials. No third-party code was copied for this package. No additional license grant or license change is introduced here.
